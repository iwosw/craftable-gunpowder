# Настройки Craftable Gunpowder 1.1.0

Мод создаёт `config/craftablegunpowder.json` при первом запуске. Останови игру или сервер, измени файл и запусти снова. `/reload` перечитывает данные, но не сам конфиг: для изменения настроек нужен полный перезапуск. Пропущенные параметры получают значения по умолчанию. Ошибочный тип, дробное количество или значение за пределами диапазона останавливает загрузку с указанием файла и ошибки; исходный файл сохраняется. [Полный пример с настройками по умолчанию](config-example.json).

На выделенном сервере выпадение, рецепты, генерацию и достижения определяет сервер. В одиночной игре используется конфиг твоей игры. Значения прочности блоков (`oreHardness`, `deepslateOreHardness`, `oreBlastResistance`) задавай одинаковыми на сервере и клиентах, чтобы отображение процесса добычи совпадало. Генерация влияет только на новые чанки. Отключение механик не удаляет уже существующие предметы и блоки.

| Параметр | По умолчанию | Значение |
|---|---:|---|
| `compostingEnabled` | `true` | Переработка перегноя включена |
| `saltpeterChance` | `0.25` | Шанс селитры, 0…1; 1 = 100% |
| `saltpeterMin`, `saltpeterMax` | `1`, `1` | Количество селитры за успех, 1…64; равномерный случайный выбор |
| `humusConsumed` | `1` | Перегноя за попытку, 1…64; неполной стопки недостаточно |
| `consumeHumusOnFailure` | `true` | Расходовать перегной при неудаче |
| `allowFullComposter` | `false` | Разрешить переработку в заполненной компостнице |
| `sulfurDropsEnabled` | `true` | Выпадение серы из обеих разновидностей руды |
| `sulfurDropChance` | `1.0` | Шанс выпадения серы, 0…1; не влияет на Шёлковое касание |
| `sulfurMin`, `sulfurMax` | `1`, `1` | Базовое количество серы, 1…64, до применения Удачи |
| `fortuneEnabled` | `true` | Удача умножает базовое количество по ванильной формуле руд |
| `silkTouchEnabled` | `true` | Шёлковое касание даёт блок руды вместо серы |
| `explosionDecay` | `true` | Ванильное уменьшение выпадения серы при взрывах |
| `oreGenerationEnabled` | `true` | Генерация серной руды в обычном мире |
| `veinSize` | `8` | Максимальный размер жилы, 1…64 |
| `veinsPerChunk` | `6` | Попыток генерации на чанк, 0…256; 0 отключает генерацию |
| `minY`, `maxY` | `-48`, `80` | Высота генерации, −64…319; минимум ≤ максимум |
| `discardOnAirExposure` | `0.0` | Вероятность пропустить руду рядом с воздухом, 0…1 |
| `oreHardness` | `3.0` | Прочность обычной руды, 0…1000 |
| `deepslateOreHardness` | `4.5` | Прочность глубинной руды, 0…1000 |
| `oreBlastResistance` | `3.0` | Взрывоустойчивость обеих руд, 0…3600000 |
| `gunpowderRecipeEnabled` | `true` | Рецепт пороха и его открытие в книге рецептов |
| `gunpowderCount` | `8` | Пороха за крафт, 1…64 |
| `humusRecipeEnabled` | `true` | Рецепт перегноя и его открытие в книге рецептов |
| `humusCount` | `4` | Перегноя за крафт, 1…64 |
| `advancementsEnabled` | `true` | Пять видимых достижений мода |
| `finalAdvancementExperience` | `50` | Опыт за достижение крафта пороха, 0…1000000 |

Минимум количества не может превышать максимум. В творческом режиме перегной не расходуется. Настройки серы общие для каменной и глубинной руды. Чтобы руда вообще ничего не давала, выключи и `sulfurDropsEnabled`, и `silkTouchEnabled`.

Пример частичного конфига: гарантированная селитра, 2–3 серы с руды, 16 пороха за крафт:

```json
{
  "saltpeterChance": 1.0,
  "sulfurMin": 2,
  "sulfurMax": 3,
  "gunpowderCount": 16
}
```

JSON не поддерживает комментарии и завершающие запятые. Булевы значения пиши как `true` или `false`, без кавычек.

Достижения: «Порох своими руками» → «Химия в компостнице» → «Всё по рецепту» → «Сам себе крипер»; отдельная ветка — «Жёлтое сокровище». Последнее достижение требует крафта именно по рецепту мода; получение пороха от крипера его не выдаёт. Автокрафтер не выдаёт личное достижение игроку. Отключение достижений не отключает книгу рецептов. Уже полученный опыт не отбирается.

Папка `config/craftablegunpowder-generated/` служебная и пересоздаётся из конфига. Не редактируй её вручную. Мод автоматически подключает обязательный пакет данных `craftablegunpowder_config`, в том числе для уже существующих миров и одиночной игры. Для замены состава/формы рецептов и других сложных изменений можно использовать обычный datapack с более высоким приоритетом.
